# 阅迹内容契约

需要修改的唯一默认入口是项目根目录 `data/reading.json`。正式结构以 `data/reading.schema.json` 为准。

- `language`：根据用户平时自然交流的语言静默选择 BCP 47 标签；用户明确指定时覆盖。
- `ui`：可选界面文案覆盖。中文与英文无需填写；其他语言必须完整覆盖界面文字。

## 文档层

- `id`：稳定且唯一；内容发生不兼容变化时更换，避免旧的本地标记串入新作品。
- `title`：来源作品或本次阅读体验的标题。
- `summary`：材料正在处理的问题，不写宣传语。
- `thesis`：这一遍阅读最值得保持的核心张力。
- `invitation`：告诉读者接下来如何参与。
- `source`：来源名称、链接与权利说明。

## 分组层

分组表达材料的认知结构，而非分页。`index` 和 `kicker` 是视觉导航；`shortTitle` 用于侧栏；`title` 与 `description` 共同说明这一步发生了什么。

## 阅读位置

- `id`：全篇唯一。
- `role`：`core`、`support` 或 `turn`。
- `quote`：必要且准确的原文短引。
- `context`：为什么此处值得停，以及它与前后结构的关系。
- `prompt`：读者需要亲自定位的经验、前提、证据或分歧。

## 质量检查

- 删除任一位置后，阅读路径是否真的变弱？如果没有，删除它。
- `context` 是否只是在换句话复述 `quote`？如果是，重写。
- `prompt` 是否能够用原文直接抄出答案？如果可以，它不是判断问题。
- 多个问题是否只是同一句式替换关键词？如果是，重新寻找差异化认知动作。
- 短引是否超出公开传播所必需的范围？如果是，缩短或改为概述。
