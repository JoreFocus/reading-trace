# 从一次性页面到阅迹

这不是一份逐像素修改日志，而是对关键设计决策的复盘。每次迭代都用同一组问题记录：

```text
观察 -> 假设 -> 改动 -> 结果 -> 原则
```

## 1. 从“展示内容”改成“留下判断”

**观察**

最初的页面能够漂亮地排列命题，但读者读完以后，页面没有发生变化。它仍然只是作者或 Agent 的输出。

**假设**

阅读面板的价值不在于更好看地展示信息，而在于允许读者覆盖、补充和反对页面中的判断。

**改动**

每条内容增加五档态度标注；标记状态进入统计，并保存在本地。

**结果**

页面从“内容展板”变成了“读者与文本交手的现场”。

**原则**

> 阅读界面的第一主体不是内容，而是读者的动作。

## 2. 标注不能只是换一个颜色

**观察**

单纯给卡片染色虽然直观，却没有推动读者继续思考。特别是“部分认同、保留、反对”很容易沦为情绪按钮。

**假设**

低认同是最有信息量的位置。界面应该在这里减速，而不是迅速完成一次点击。

**改动**

读者选择部分认同、保留或反对时，自动出现针对该状态的追问：

- 哪一部分不能接受？
- 正在等待什么证据？
- 问题出在前提、推理还是经验？

**结果**

颜色不再是装饰，而成为不同认知动作的入口。

**原则**

> 每一种视觉状态，都必须对应一种不同的思考行为。

## 3. 进度不是“看了多少”，而是“判断了多少”

**观察**

传统阅读进度只说明滚动位置，无法说明读者是否真正参与。

**假设**

在伴读场景中，完成不是滑到页面底部，而是对值得停留的位置形成了判断。

**改动**

顶部进度改为“已标记条目 / 总条目”，同时呈现各类判断分布。

**结果**

进度从消费指标变成参与指标。

**原则**

> 指标应奖励想要发生的行为，而不是最容易测量的行为。

## 4. 筛选不是检索，而是重新阅读

**观察**

标记完成后，读者真正想回看的常常不是某个章节，而是“我所有迟疑的位置”或“真正击中我的句子”。

**假设**

态度本身可以成为第二条阅读路径。

**改动**

增加未标、击中、认同、部分、保留、反对筛选；目录继续保留文本原始结构。

**结果**

同一份文本同时拥有两张地图：

```text
作者的章节结构
读者的判断结构
```

**原则**

> 好的阅读工具既保存作者的秩序，也显露读者的秩序。

## 5. 导出不是备份，而是把阅读交给下一步

**观察**

如果标注只能留在页面中，阅读过程仍然是一个孤岛。

**假设**

阅读结果应该能够自然进入写作、讨论和知识管理。

**改动**

导出内容同时包含原文、判断与读者备注，使用普通 Markdown，不绑定特定平台。

**结果**

面板不再是终点，而成为“阅读 -> 思考 -> 写作”之间的接口。

**原则**

> 可导出的不是数据，而是仍然保有上下文的思考。

## 6. 从固定页面拆成数据与界面

**观察**

静态 HTML 可以完成一次作品，却很难被下一篇文章复用。

**假设**

真正需要稳定的不是内容，而是内容与界面之间的契约。

**改动**

把文本拆成通用数据：

```text
文档
├── 来源与总论
├── 章节
│   └── 阅读位置
│       ├── 原文
│       ├── 结构角色
│       ├── 必要上下文
│       └── 碰撞问题
└── 可配置标签
```

**结果**

视觉系统可以换文章，数据也可以换另一种界面。

**原则**

> 先找到稳定的数据关系，再决定它应该长成什么样。
