# 与 Agent 一起创造阅迹

这里不提供一份标准提示词。阅迹希望交付的是一套可迁移的判断方式，而不是把所有材料压进同一个生产模具。

## 一、先判断你手里是什么

### 原始材料

文章、书摘、直播文稿或演讲转录，还没有经过伴读。此时先理解作者在处理什么问题，再决定哪些位置值得读者停下来。

### 已有伴读记录

已经包含结构判断、关键引文和提问。此时不要重新“总结一遍”，而要辨认其中最有张力的阅读路径，并转译成阅迹的数据关系。

### 个人复盘标注

已经带有你的判断和经验。此时最重要的是保留声音：哪些是原作者的话，哪些是你的理解，哪些问题应该继续交给下一位读者。

## 二、寻找材料自己的组织力

不要默认按原文段落切卡片。可以从这些关系中选择最有解释力的一种：

- 一个矛盾如何逐步展开；
- 一个问题如何换了三次问法；
- 一个结论依靠哪些支撑成立；
- 讲者在哪个位置改变了方向；
- 读者的理解在哪些位置可能发生变化。

分组数量由材料决定。删掉一个分组仍不影响理解，说明它可能只是排版单位。

## 三、挑选“值得停下来的位置”

一个阅读位置至少应满足一项：

- 它改变了后文的理解方式；
- 它暴露了一个关键前提；
- 它容易被迅速认同，却值得迟疑；
- 它与读者经验可能发生真实碰撞；
- 它使前后两个判断之间出现转折。

不是每个金句都值得成为阅读位置。金句适合转发，阅迹位置必须能够生成判断。

## 四、写三种不同的话

`quote` 保留材料的声音，`context` 说明结构意义，`prompt` 把选择权交给读者。

好的 `context` 不只是复述，而是回答“为什么此处值得停”。好的 `prompt` 不考察记忆，也不暗示标准答案，而是让读者定位自己的经验、前提或分歧。

## 五、让形式跟随内容

默认只替换 `data/reading.json`。如果材料出现现有界面表达不了的关系，再扩展视觉：

- 多方对话可能需要并列视角；
- 时间演化可能需要时间轴；
- 论证争议可能需要证据与反证；
- 个人复盘可能需要“当时 / 现在”的双层判断。

不要因为会写代码就增加组件。只有新的认知动作，才值得新的界面。

## 六、发布前再做一次权利判断

区分“我可以阅读”与“我可以公开传播”。对于直播文稿、付费内容、内部材料或他人创作：

- 取得授权，或只在许可范围内分享；
- 避免连续、大段复现原文；
- 明确作者、讲者、来源和你的原创部分；
- 不确定时使用私有预览。

## 完成标准

一份阅迹不是“JSON 校验通过”就完成。还要能回答：

- 读者第一眼知道该如何参与吗？
- 原文、系统理解与读者判断能一眼区分吗？
- 每个停顿位置都真的值得一次判断吗？
- 材料自己的声音还在吗？
- 导出的轨迹脱离网页后仍然成立吗？
