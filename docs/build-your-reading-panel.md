# 打造你自己的阅读面板

阅读面板不是把文章切成卡片。它是在回答：阅读时，哪些内在变化值得被看见？

## 一、先定义你希望发生的阅读行为

不要先选配色。先写下读者应该做什么。

例如：

- 找出作者真正想说服你的地方；
- 区分事实、解释和判断；
- 标记认同与抵抗；
- 为迟疑写下原因；
- 把多次停顿连成一条理解轨迹。

如果界面上一个元素不能推动这些行为，它大概率只是装饰。

## 二、分开三类信息

```text
原文事实：作者确实写了什么
系统判断：这一段在结构中起什么作用
读者判断：我接受什么、拒绝什么、为什么
```

三者不能混在同一种视觉层级里。否则 Agent 的解释会伪装成原文，读者的判断也会被系统预先规定。

## 三、先建信息模型

最小阅读位置可以只包含：

```json
{
  "id": "I-01",
  "role": "core",
  "quote": "原文",
  "context": "为什么把它放在这里",
  "prompt": "读者必须亲自回答的问题"
}
```

之后再增加来源、章节、翻译、术语或证据。不要为了页面丰富，先创造没有用途的字段。

## 四、建立视觉语法

每一种视觉变化都回答一个问题：

| 视觉变量 | 适合表达 |
| --- | --- |
| 位置、缩进 | 层级与从属 |
| 大小、字重 | 重要程度 |
| 颜色 | 状态或类别 |
| 边框、底纹 | 来源或证据边界 |
| 动效 | 状态刚刚发生变化 |

不要让同一种颜色同时表示“重要”“认同”和“已完成”。一个视觉变量承担多个含义，会让页面失去语法。

## 五、设计完整反馈回路

一次有效动作至少经历：

```text
读者点击
   ↓
局部状态立即改变
   ↓
整体进度得到更新
   ↓
需要时出现进一步追问
   ↓
结果可以被回看和导出
```

如果点击之后只换一个颜色，这个回路还没有闭合。

## 六、用低认同位置检验面板

“认同”通常很顺滑，真正暴露设计能力的是：

- 部分认同后，面板是否帮助定位分歧？
- 暂时保留时，能否记录等待的证据？
- 不同意时，能否区分情绪反应与论证反驳？

好的面板不会逼读者达成一致，而会提高分歧的清晰度。

## 七、记录迭代，不记录审美情绪

每次修改只记录五件事：

```text
观察：实际发生了什么
假设：为什么会这样
改动：这次只改变什么
结果：行为是否真的变化
原则：别人能否迁移这次经验
```

“感觉更高级”无法复用。“降低了原文与操作按钮之间的视觉竞争”才是可以传递的经验。

## 八、发布前的自检

- 不看说明，读者知道第一步做什么吗？
- 原文、系统解释、读者输入能否一眼区分？
- 键盘、触摸屏和窄屏是否都能完成核心动作？
- 刷新页面后，阅读状态是否仍在？
- 导出结果脱离本页面后是否还能看懂？
- 删除所有装饰后，交互关系是否仍然成立？
- 换一篇完全不同的文本，是否只需更换数据？

最后一个问题最重要。能换内容而不重做页面，面板才从一次作品变成了工具。
